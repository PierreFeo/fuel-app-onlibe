# START HERE — пошаговая инструкция для новичка

Этот файл для ТЕБЯ (человека). Файлы `CLAUDE.md` и `docs/` — для Claude Code: это «техзадание»,
которое он читает перед работой, чтобы не придумывать архитектуру каждый раз заново.

---

## Как всё устроено (в двух словах)
- **Android-приложение** — то, что у сотрудника в телефоне. Пишем на Kotlin в Android Studio.
- **Backend** — программа на твоём VDS-сервере. Хранит данные в базе PostgreSQL и отвечает
  приложению по интернету (REST API).
- **SMS-шлюз** — старый Android-телефон дома с SIM-картой и приложением SMS Gateway for Android.
  Backend просит его отправить SMS с кодом входа.
- **Claude Code** — ИИ-программист в терминале. Ты говоришь, что сделать, он пишет код,
  запускает тесты и показывает изменения. Ты проверяешь и принимаешь.

Порядок работы: сначала backend на своём компьютере → потом Android-приложение, которое
ходит в локальный backend → потом реальные SMS → потом перенос backend на VDS.

## Шаг 1. Установить программы
| Программа | Зачем | Где взять |
|---|---|---|
| Git | история изменений кода, откат ошибок | git-scm.com (на Windows — Git for Windows) |
| Android Studio | писать и запускать Android-приложение | developer.android.com/studio |
| Docker Desktop | запускать backend и базу одной командой, без установки Python/PostgreSQL | docker.com |
| Claude Code | ИИ-ассистент для кода | см. ниже |

**Установка Claude Code** (нужна платная подписка Claude или аккаунт в Claude Console):
- macOS / Linux, в Терминале: `curl -fsSL https://claude.ai/install.sh | bash`
- Windows, в PowerShell: `irm https://claude.ai/install.ps1 | iex`

Проверка: открыть новый терминал, набрать `claude` → при первом запуске он попросит войти
в аккаунт через браузер. Выход из Claude Code — `/exit` или два раза Ctrl+C.
Актуальная документация: https://code.claude.com/docs

## Шаг 2. Подключить Claude Code к Android Studio
1. Android Studio → **Settings → Plugins → Marketplace** → найти **«Claude Code [Beta]»**
   (автор Anthropic) → Install → перезапустить Android Studio.
2. Внизу Android Studio открыть вкладку **Terminal** и набрать `claude`.
   Плагин сам подхватит сессию: изменения кода будут открываться во встроенном просмотре
   различий (diff), а выделенный тобой код — автоматически попадать Claude в контекст.
3. Если запускаешь Claude в отдельном (внешнем) терминале — набери внутри него `/ide`,
   чтобы связать его с Android Studio.
4. Настройки плагина: **Settings → Tools → Claude Code [Beta]**.

## Шаг 3. Создать папку проекта и положить контракты
1. Создай папку, например `C:\dev\fuel-app` или `~/dev/fuel-app`.
2. Распакуй туда все файлы из архива так, чтобы получилось:
   ```
   fuel-app/
   ├── CLAUDE.md
   ├── START_HERE.md
   ├── .gitignore
   ├── .claude/commands/   (next-step.md, check.md, explain.md)
   ├── docs/               (01…09 + DECISIONS.md)
   ├── backend/            (CLAUDE.md, .env.example)
   └── android/            (CLAUDE.md)
   ```
   Папки `.claude` и файл `.gitignore` начинаются с точки — на macOS они скрыты
   (показать: Cmd+Shift+.), на Windows включи «Показывать скрытые элементы».
3. **Прочитай `docs/01_PRODUCT.md` и `docs/06_BUSINESS_RULES.md`** и поправь под свою организацию:
   поля автомобиля, способы оплаты, формулы расхода. Это самое важное — Claude будет делать
   ровно то, что там написано.
4. Сделай первый коммит. В терминале в папке `fuel-app`:
   ```bash
   git init
   git add .
   git commit -m "Контракты проекта"
   ```
   (По желанию: создай приватный репозиторий на GitHub и сделай `git push` — это резервная копия.)

## Шаг 4. Backend (фазы 1–3 roadmap)
1. Запусти Docker Desktop.
2. Открой терминал в папке `fuel-app` (корень!) и запусти `claude`.
3. Напиши: `/next-step` — Claude возьмёт задачу 1.1 из `docs/08_ROADMAP.md`, покажет план,
   после твоего «ок» напишет код и тесты.
4. Проверь сам то, что указано в «Готово, когда» (например, открыть http://localhost:8000/docs).
5. Если всё работает — коммит: `git add . && git commit -m "1.1 каркас backend"`.
6. Набери `/clear` (очистить контекст) и снова `/next-step`. И так задача за задачей.

Для backend Android Studio не обязательна — можно работать прямо в терминале
(или открыть папку `backend` в бесплатном VS Code / PyCharm Community).

## Шаг 5. Android-приложение (фазы 4–5)
1. Android Studio → **New Project → Empty Activity** (шаблон с Jetpack Compose):
   - Name: `FuelTracker`
   - Package name: например `ru.mycompany.fuel`
   - Save location: **`…/fuel-app/android`** (именно эта папка! в ней уже лежит `CLAUDE.md` — это нормально)
   - Language: Kotlin · Minimum SDK: API 26 · Build configuration language: Kotlin DSL
2. Дождись окончания Gradle Sync, создай эмулятор (**Device Manager → Create Device**,
   например Pixel, свежий образ Android) и нажми ▶ Run — должно открыться «Hello Android».
3. Закоммить: `git add . && git commit -m "4.1 пустой Android-проект"`.
4. Во вкладке Terminal Android Studio (она откроется в папке `android`) запусти:
   ```bash
   claude --add-dir ..
   ```
   `--add-dir ..` даёт Claude доступ к папке `docs/` уровнем выше. Корневой `CLAUDE.md`
   он подхватывает сам.
5. Дальше так же: `/next-step` → проверка → коммит → `/clear`.
6. Backend при этом должен быть запущен (`docker compose up -d` в папке `backend`) —
   приложение на эмуляторе обращается к нему по адресу `http://10.0.2.2:8000`
   (это «localhost твоего компьютера» с точки зрения эмулятора).

## Шаг 6. Реальные SMS (фаза 6)
1. Подготовь домашний телефон по инструкции в `docs/05_AUTH_SMS.md` (раздел «Настройка домашнего телефона»).
2. Проверь отправку командой `curl` оттуда же.
3. Впиши логин/пароль шлюза в `backend/.env`, поставь `SMS_PROVIDER=smsgate`,
   перезапусти backend: `docker compose up -d`.
4. Попроси Claude выполнить задачу 6.2.

## Шаг 7. Перенос на VDS (фаза 7)
Понадобится: VDS с Ubuntu, доменное имя (например `fuel.mycompany.ru`), направленное на IP сервера.
Попроси Claude: *«Выполни задачу 7.1, а для 7.2 дай мне пошаговые команды для Ubuntu,
объясняя каждую»*. Caddy сам получит HTTPS-сертификат. В приложении для release-сборки
указывается адрес `https://fuel.mycompany.ru/api/v1/`.

## Как писать запросы Claude Code
**Хороший запрос = что сделать + где правила + как проверить + ограничения.**

Плохо:
> сделай авторизацию

Хорошо:
> Выполни задачу 2.2 из docs/08_ROADMAP.md. Правила — в docs/05_AUTH_SMS.md, формат ответов и
> ошибок — в docs/04_API_CONTRACT.md. Сначала покажи план. Напиши тесты на: неверный код,
> истёкший код, 6-ю попытку, повторный запрос раньше 60 секунд, номер не из белого списка.
> Реальные SMS не отправляй — только FakeSmsSender.

Полезные приёмы:
- **`@файл`** — сослаться на конкретный файл: `Посмотри @docs/06_BUSINESS_RULES.md и проверь sheet_calc.py`.
- **Режим планирования** — нажми **Shift+Tab** (переключает режимы), Claude будет только
  анализировать и предлагать план, ничего не меняя. Удобно для больших задач.
- **Esc** — остановить Claude, если он пошёл не туда. Потом уточни задачу.
- **`/clear`** — между задачами. Длинная «замусоренная» сессия делает ответы хуже.
- **Ошибка?** Скопируй текст ошибки целиком и вставь: *«При запуске вылетает вот это: … Найди
  причину и исправь, объясни, что было не так»*.
- **Скриншот** — можно перетащить картинку в терминал Claude Code: *«Карточка выглядит так,
  а должна как в docs/07_UI_SCREENS.md — поправь»*.
- **Не понимаешь код?** `/explain app/services/sheet_calc.py` — объяснит простыми словами.
- **Перед коммитом** — `/check`: сверит код с контрактами и прогонит тесты.
- **Хочешь изменить требования?** Сначала попроси поправить документ в `docs/`, потом код.
  *«Хочу добавить поле "водитель" в заправку. Обнови 03_DATA_MODEL, 04_API_CONTRACT и 07_UI_SCREENS,
  покажи изменения, потом реализуй»*.

Claude спрашивает разрешение перед изменением файлов и запуском команд. Читай, что он
предлагает: если непонятно — спроси «что делает эта команда?» перед тем как разрешить.

## Как тестировать (подробнее — `docs/09_TESTING.md`)
1. **Автотесты** — их пишет Claude. Запуск backend: `docker compose exec api pytest -q`
   (в папке `backend`); Android: `./gradlew test` (в папке `android`). Зелёные — хорошо.
2. **Backend руками** — открой http://localhost:8000/docs → `request-code` → Try it out →
   код смотри в `docker compose logs -f api` → `verify-code` → скопируй `access_token` →
   кнопка **Authorize** вверху → теперь можно вызывать остальные методы.
3. **Приложение руками** — на эмуляторе пройди чек-лист из `docs/09_TESTING.md`.
4. **На своём телефоне** — включи «Для разработчиков» → «Отладка по USB», подключи кабелем,
   выбери телефон вверху Android Studio и нажми ▶. Телефон и компьютер — в одной Wi-Fi,
   `BASE_URL` — IP компьютера (Claude подскажет, как переключить).

## Золотые правила
1. Одна задача — одна сессия — один коммит. Если Claude всё сломал: `git restore .` вернёт
   файлы к последнему коммиту.
2. Никогда не коммить `.env` и пароли (`.gitignore` уже защищает).
3. Не принимай код, который не проверил руками хотя бы по пункту «Готово, когда».
4. Документы в `docs/` — главнее кода. Меняются требования — сначала документ.
5. Застрял больше чем на 20 минут — спроси Claude: *«Я новичок, объясни, что происходит
   и какие есть варианты»*.

## Частые проблемы
| Симптом | Причина / решение |
|---|---|
| Приложение «не видит» сервер на эмуляторе | адрес должен быть `10.0.2.2`, а не `localhost`; backend запущен? |
| `CLEARTEXT communication not permitted` | Android запрещает http — нужен network_security_config для debug (попроси Claude) |
| `Cannot connect to the Docker daemon` | не запущен Docker Desktop |
| Gradle Sync падает | File → Invalidate Caches → Restart; скопируй ошибку Claude |
| SMS не приходят | телефон-шлюз в сети? приложение не «уснуло»? отключена оптимизация батареи? баланс SIM? |
| Claude не видит docs/ при работе из android/ | запускай `claude --add-dir ..` |
