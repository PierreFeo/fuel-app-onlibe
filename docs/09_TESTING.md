# 09. Тестирование

## Пирамида
1. **Unit-тесты** (больше всего): `sheet_calc`, нормализация телефона, OTP-хэш, JWT, ViewModel-логика.
2. **API-тесты backend**: каждый эндпоинт через `httpx.AsyncClient` и тестовую БД.
3. **Android-тесты сети**: Retrofit + MockWebServer (разбор JSON, ошибок, refresh токена).
4. **Ручная проверка** человеком по чек-листу ниже (после каждой фазы).

## Backend
- Тестовая БД: отдельная база `fuel_test` в том же контейнере PostgreSQL; перед каждым тестом —
  чистые таблицы (транзакция с откатом или truncate).
- SMS в тестах — только `FakeSmsSender`. Реальные запросы во внешние сервисы в тестах ЗАПРЕЩЕНЫ.
- Время — через инъекцию «часов» (`now()` как зависимость), чтобы тестировать истечение кода.
- Для каждого эндпоинта минимум: успешный сценарий, без токена (401), чужой ресурс (404),
  невалидные данные (400/422).
- Запуск: `docker compose exec api pytest -q` · покрытие: `pytest --cov=app`.
- Цель покрытия: `services/` ≥ 90 %, в целом ≥ 75 %.

## Android
- `./gradlew test` — unit-тесты (JVM, быстро).
- `./gradlew connectedAndroidTest` — UI-тесты на эмуляторе (для ключевых экранов: вход, карточка ЛУТ).
- ViewModel тестируются с фейковым репозиторием, без сети.
- Форматирование чисел/месяцев (`45,50 л`, «Октябрь 2026») — unit-тесты.

## Ручной чек-лист (сквозной сценарий)
1. Вход по номеру → код в логах backend (`docker compose logs -f api`) → ввод кода → ввод имени.
2. Добавить авто «Lada Vesta», бак 50, норма 8,5 → выбрать.
3. Создать лист за текущий месяц: пробег 52340, остаток 12.
4. Добавить 2 заправки по 40 л × 55 ₽ → «Заправлено 80,00 л · 4 400,00 ₽», «Доступно 92,00 л».
5. Закрыть месяц: пробег 53340, факт. остаток 10 → итоги совпадают с примером A из `06_BUSINESS_RULES.md`.
6. «Новый лист» → подставились пробег 53340 и остаток 10,00.
7. Попробовать добавить заправку в закрытый лист → кнопки нет; переоткрыть → появилась.
8. Выйти → вход снова требует код.
9. Перезапустить приложение → сразу открывается лента выбранного авто (токен сохранён).
