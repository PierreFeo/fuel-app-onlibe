# 08. Roadmap — план по шагам

Правило: одна задача = одна сессия Claude Code = один коммит.
После каждой задачи — отметить `[x]` в этом файле.
«Готово, когда» — критерий, который проверяет ЧЕЛОВЕК своими руками.
Обясняй что и как работает после каэдого шага максимально понятно.

## Фаза 6. Офлайн-режим и синхронизация
Данные и расчёты переезжают на телефон, сервер становится хранилищем копии (`02_ARCHITECTURE.md`).
Порядок важен: старые эндпоинты сервера удаляются только в конце (6.13), чтобы приложение
работало после каждого шага.
- [x] 6.0 Документы: офлайн, синхронизация, гостевой режим, пароль в профиле, расчёты на телефоне
- **Backend**
- [x] 6.1 Поля синхронизации: `version` из `sync_version_seq`, `deleted_at`, частичный UNIQUE листов,
  `users.name_version`; миграция; id записей может прийти от клиента
- [x] 6.2 `POST /sync`: приём изменений, `rejected`, курсор, мягкое удаление, выдача изменений
  - Готово, когда: в Swagger `/sync` с `cursor: null` и новым авто → авто вернулось с курсором;
    повторный `/sync` с этим курсором → пустые списки; тесты (успех, 401, чужой id, нет родителя,
    `SHEET_EXISTS`, удаление, частичное отклонение) зелёные
- [x] 6.3 `PUT /me/password` + `has_password` в `/me` и ответах входа
  - Готово, когда: задал пароль через Swagger → `/auth/login` с ним пускает без SMS
- **Android**
- [x] 6.4 Room: зависимость, таблицы, DAO, служебные поля `is_dirty` / `is_deleted` / `change_seq`; тесты DAO
- [x] 6.5 `SheetCalculator`, проверки, `next-prefill` на Kotlin; эталонные примеры A–I и предупреждения
  как unit-тесты
- [x] 6.6 Репозитории авто, листов и заправок — на Room; экраны на Flow; без пагинации и
  pull-to-refresh; карточка и формы считают и проверяют на телефоне
  - Готово, когда: в режиме полёта на эмуляторе можно добавить авто, лист, заправки, закрыть месяц —
    цифры как в примере A
- [x] 6.7 Режимы `GUEST` / `ACCOUNT`, Splash, «Продолжить без входа», имя гостя
- [x] 6.8 Движок синхронизации (`SyncRepository`): сбор изменений, `POST /sync`, обработка ответа,
  `rejected`, курсор, обновление токена; тесты с MockWebServer
- [ ] 6.9 Профиль: блок «Синхронизация», SyncAfterLogin после входа, «Войдите снова», гость → вход
  с объединением данных
  - Готово, когда: гость завёл авто и лист → вошёл → данные на сервере (видно в Swagger `/sync`)
- [ ] 6.10 Пароль в профиле (задать / сменить), вход по нему без SMS
- [ ] 6.11 Выход: синхронизация → очистка телефона; без интернета выйти нельзя
- [ ] 6.12 Смена телефона: вход на «чистом» эмуляторе получает все данные аккаунта
  - Готово, когда: данные, созданные на одном эмуляторе, после входа появились на втором
- [ ] 6.13 Удалить старые эндпоинты (`/cars`, `/sheets`, `/refuelings`) и `sheet_calc.py` на сервере,
