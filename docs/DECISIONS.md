# Журнал решений (ADR-lite)

Записывать сюда каждое заметное решение: что выбрали, почему, какие были альтернативы.
Новые записи — сверху. Формат: дата · решение · причина.

- 2026-10 · Заправки (3.4): дата вне месяца листа — 422 `BUSINESS_RULE`, `reason: REFUELING_DATE_OUTSIDE_MONTH`; изменение/удаление заправки, после которого фактический остаток больше доступного топлива, — 422 `FUEL_END_OVER_AVAILABLE` · правила 3 и 4 действуют при любом изменении листа, а не только при вводе остатка
- 2026-10 · Сумма заправки в PATCH: передана — берём как есть (скидки); `null` или сменились литры/цена без суммы — пересчёт литры × цена; рассчитанная сумма не влезает в NUMERIC(10,2) — 400 по полю `total_cost`. `station`/`note`: пробелы обрезаются, пустая строка = `null`; `null` в PATCH стирает `odometer_km`/`station`/`note`, для даты, литров, цены и способа оплаты — 400 · иначе после правки литров в карточке осталась бы старая сумма
- 2026-10 · ЛУТ (3.3): пагинация `limit` 1..50 (по умолч. 12), `before=YYYY-MM` — строго раньше, `next_before` — месяц последнего листа страницы; «предыдущий лист» для `ODOMETER_GAP` — ближайший более ранний, даже через пропуск месяцев · контракт не уточнял, так проще всего для ленты
- 2026-10 · Ошибки формата поля (минусы, год/месяц вне диапазона, нет `odometer_end_km` при close) — 400; правила, зависящие от данных в БД, — 422 `BUSINESS_RULE` с `details.reason`: `ODOMETER_END_BEFORE_START`, `FUEL_END_OVER_AVAILABLE`, `MONTH_TOO_FAR`, `SHEET_HAS_REFUELINGS`, `WINTER_NORM_NOT_SET` · приложение различает причины по одному полю
- 2026-10 · Закрытый лист: PATCH, close и DELETE → 409 `SHEET_CLOSED`; reopen открытого листа — 200 без изменений; PATCH с тем же сезоном норму не перекопирует; «текущий месяц» — по UTC (`get_now`); по архивному авто листы можно читать и создавать · правило 6 «нормы меняются только при переключении», единое время в проекте
- 2026-10 · Сезон первого листа без явного `season` — по месяцу самого листа, а не по текущему · иначе лист на ноябрь, созданный в октябре, стал бы «летним»

- 2026-10 · Сезонные нормы по образцу старого приложения MyFuel: у авто летняя и зимняя норма; у листа `season`, переключается вручную иконкой ☀️/❄️ и наследуется следующим месяцем; первый лист — по месяцу (`WINTER_MONTHS`, по умолч. 11–3) · зимний период зависит от региона и может начаться в середине месяца — решает пользователь; переключать нужно только 2 раза в год. Альтернатива «автоматически по месяцу» отклонена
- 2026-10 · Нормы и расход на 100 км — 3 знака после запятой (NUMERIC(6,3)), литры и деньги — 2 · реальные нормы вида 10.068; при 2 знаках цвет расхода в пограничных случаях был бы неверным
- 2026-10 · Цвет расхода считает backend: `calc.consumption_status` NORMAL/OVER (≤ нормы — зелёный) · правило в одном месте, Android только красит (правило №10)
- 2026-10 · Цена за литр остаётся обязательной, АЗС — необязательной · решение пользователя: деньги в ЛУТ нужны всегда

- 2026-10 · Расчёты ЛУТ: зависимые поля берут округлённые значения других полей; каждое предупреждение — не больше раза; одометр заправки без конца месяца проверяется только снизу · цифры в карточке сходятся «на глаз», без дублей предупреждений
- 2026-10 · Покрытие тестами считается с `concurrency = greenlet` · иначе coverage не видит код внутри SQLAlchemy async и занижает цифры
- 2026-10 · Авто: список по дате добавления; госномер в верхний регистр; возврат из архива через `PATCH is_archived=false`; неверный UUID в пути — 400 · контракт («любые поля Car») это допускает, другого способа вернуть авто нет
- 2026-10 · Общий тип `Decimal2` (app/schemas/types.py) для литров, денег, норм: вход — строка или число, ≤ 2 знаков; выход — строка «50.00» · одно правило для всех дробных полей API
- 2026-10 · Refresh-токен живёт 90 дней (не 30), срок продлевается при каждом refresh · ЛУТ заполняют раз в месяц — при 30 днях сотрудник разлогинивался бы почти каждый месяц
- 2026-10 · `/auth/logout` всегда 204, даже с недействительным токеном · выход не должен «застревать» в приложении; access-токен истекает сам за 15 мин. Срок JWT сверяется с часами приложения (`get_now`), не системными · единое время для всей логики и тестов
- 2026-10 · Выдача JWT (access + запись refresh в `refresh_tokens`) сделана в задаче 2.2, а не 2.3 · по контракту verify-code сразу возвращает токены; в 2.3 остаются проверка токенов, refresh, logout, `/me`
- 2026-10 · Отключённый пользователь (`is_active=false`) на request-code получает 403 `PHONE_NOT_ALLOWED` · контракт не меняется, SMS не тратится
- 2026-10 · Лимит запросов кода по IP — счётчик в памяти процесса (`SlidingWindowLimiter`), время — зависимость `get_now` · как в 05_AUTH_SMS для MVP; часы подменяются в тестах

- 2026-10 · Запасной вход по паролю (`POST /auth/login`), логин = номер телефона, пароль выдаёт человек командой `python -m app.cli set-password`; пользователь пароль не меняет; тестового аккаунта для пароля нет · если SMS не пришла, задать пароль через приложение невозможно; отдельный логин не нужен — телефон уже уникален. Альтернативы: отдельное поле login, смена пароля в профиле — отклонены для MVP
- 2026-10 · Хэш паролей — `hashlib.scrypt` (stdlib), блокировка 15 мин после 5 ошибок · без новой зависимости (bcrypt/argon2 не нужны для десятков пользователей), защита от подбора

- 2026-10 · Enum-поля в БД — varchar + CHECK (`native_enum=False`), не PostgreSQL ENUM · совпадает с 03_DATA_MODEL (varchar), новое значение добавляется без ALTER TYPE
- 2026-10 · UUID первичных ключей генерирует Python (uuid4), не БД · id известен до INSERT; единые имена ограничений (naming convention) для стабильных миграций
- 2026-10 · uvicorn как ASGI-сервер, база `fuel_test` создаётся init-скриптом PostgreSQL · стандартный сервер для FastAPI; тестовая БД в том же контейнере, как требует 09_TESTING.md
- 2026-10 · Монорепо (backend + android в одном репозитории) · проще новичку, Claude видит контракт и обе стороны сразу
- 2026-10 · Backend на Python/FastAPI · простой синтаксис, автодокументация Swagger, удобно тестировать
- 2026-10 · Расчёты ЛУТ только на backend · одна точка истины, Android не дублирует формулы
- 2026-10 · Дробные числа в API — строки · исключить ошибки float в литрах и деньгах
- 2026-10 · SMSGate в режиме Cloud на старте · домашний телефон за NAT, не нужен проброс портов
- 2026-10 · Норма расхода копируется в ЛУТ при создании · смена нормы не меняет прошлые месяцы
- 2026-10 · MVP без офлайна · сократить сложность; добавить Room позже при необходимости
- 2026-10 · Ошибки валидации — 400 `VALIDATION_ERROR` (не 422 FastAPI); неизвестный URL/метод — 404 `NOT_FOUND`; сбой — 500 `INTERNAL_ERROR` · 422 зарезервирован под `BUSINESS_RULE`, клиенту достаточно одного кода «не найдено»
