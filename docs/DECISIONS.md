Новые записи — сверху. Формат: дата · решение · причина.

- 2026-10 · Действия с ЛУТ (5.4): «Новый лист» — FAB → `next-prefill` → NewSheetDialog (месяц листается ‹ ›, сезон ❄️ Зима | ☀️ Лето; «Зима» неактивна, если у авто нет зимней нормы), сезон отправляется явно; новый лист вставляется в ленту по месяцу без перезагрузки. CloseSheetDialog подставляет уже введённые пробег/остаток; клиент проверяет формат и «конец ≥ начала», «остаток ≤ доступного» — сервер. Ошибки внутри диалогов (409 `SHEET_EXISTS`, 422 с текстом сервера, нет связи) показываются в самом диалоге — Snackbar под диалогом не виден. Меню ⋮ карточки: «Переоткрыть» (закрытый лист), «Удалить» (только лист без заправок, с подтверждением)
- 2026-10 · Переключение сезона — нажатием на «☀️ Лето / ❄️ Зима» в карточке: открытый лист → `PATCH {season}`, Snackbar «Сезон: зима. Норма N»; 422 `WINTER_NORM_NOT_SET` → Snackbar «Зимняя норма не указана» с кнопкой «Указать» (CarEditScreen авто); закрытый → «Месяц закрыт. Сначала переоткройте его». После возврата на ленту шапка авто тихо перезагружается (могла появиться зимняя норма). Пока по листу идёт запрос, его кнопки неактивны
- 2026-10 · Разбор чисел в формах вынесен в `ui/common/NumberInput.kt` (фильтр ввода, `parseKmInput`, `parseNonNegativeDecimal`, `toInputText`) — общий для формы авто и диалогов листа. Редактирование пробега на начало/конец нажатием (07_UI_SCREENS, «Открытый лист») в 5.4 не входит — пробег на конец вводится в CloseSheetDialog; вернуться при необходимости

- 2026-10 · Лента ЛУТ (5.3): шапка (GET /cars/{id}) и первая страница листов грузятся параллельно; старые листы подгружаются, когда до конца списка ≤ 3 карточек; после ошибки подгрузки автоподгрузка не повторяется — внизу «Повторить». Pull-to-refresh перезагружает первую страницу (пагинация с начала). 404 по авто или листам → выбор авто сбрасывается, открывается список авто; смена `selected_car_id` перезагружает ленту · авто могли отправить в архив с другого экрана или устройства
- 2026-10 · Карточка ЛУТ: открытый лист — «Доступно топлива» вместо итогов; закрытый — остаток на конец («(по норме)», если фактический не введён), расход с цветом по `consumption_status`, «Перерасход/Экономия N л» по знаку `deviation_l` (0 — «Ровно по норме»), «1 км = N ₽». Если расход не посчитан: нет пробега на конец — «появится после ввода пробега…», нет фактического остатка — «укажите фактический остаток в баке», пробег 0 км — ничего. Доменные модели листа — `BigDecimal`/`LocalDate`, формулы на клиенте не считаются
- 2026-10 · Действия в карточке распределены по задачам: переключение сезона ☀️/❄️, «Новый лист», «Закрыть месяц», меню (переоткрыть, удалить) — 5.4; «+ Заправка», правка/удаление заправки — 5.5. В 5.3 иконка сезона только показывает сезон (у закрытого — бледная)

- 2026-10 · Android-авто (5.2): `selected_car_id` — в том же DataStore, что и токены (`SelectedCarStorage`); `AppViewModel.session` = токены + выбранное авто: Splash и вход ведут в ленту, если авто выбрано, иначе в список авто. Выбор авто делает ленту корнем истории; из ленты список открывается поверх (со стрелкой «Назад»). Архив выбранного авто сбрасывает выбор · один файл настроек, один источник решения «куда после входа»
- 2026-10 · Список авто перезагружается при каждом показе экрана (ON_RESUME), а не через кэш/результат навигации · после CarEditScreen список свежий без лишнего кода; ошибка повторной загрузки при показанном списке — Snackbar, список не прячется. «В архив» — с диалогом подтверждения (в UI нет возврата из архива)
- 2026-10 · Форма авто: при изменении отправляются все поля (`plate_number`/`norm_winter_l_per_100km` = `null`, если стёрты); числа — `BigDecimal` без лишних нулей строкой («50», «10.068»). Проверка на клиенте повторяет сервер: обязательность, > 0, знаков после запятой ≤ 2 (бак) / ≤ 3 (нормы), размер numeric(6,·), длина name ≤ 60, plate ≤ 15; ошибки 400 из `details` сервера показываются под соответствующим полем
- 2026-10 · До 5.3 лента ЛУТ — заглушка с кнопкой «Сменить авто». В 5.3 лента должна сама уйти в список авто, если авто не выбрано или сервер ответил 404 (авто в архиве/чужое)

- 2026-10 · Android-вход (5.1): Splash решает только по наличию токена в DataStore, без запроса к серверу; `AppViewModel` следит за `TokenStorage.tokens` — если токены стёрты на экране приложения (refresh отклонён), переход на PhoneScreen с очисткой истории. После входа экраны входа убираются из back stack · быстрый старт без сети; одна точка реакции на конец сессии вместо проверки в каждом экране
- 2026-10 · Android-ошибки форм входа: ожидаемые ответы (403 номер не разрешён, 429, неверный код/пароль, 400 с текстом сервера) — красным текстом под полем; сеть и прочие ошибки — Snackbar (`error.message` или «Нет связи с сервером») · ошибку поля видно рядом с полем, Snackbar — как требует 07_UI_SCREENS для ошибок сети. - 2026-10 · `CodeRoute` дополнен `resendAfterSec` (из ответа request-code) — таймер «Отправить повторно» берёт длительность у сервера, а не константу. Иконки «показать/скрыть пароль» — свои vector drawable (Material Symbols), а не `material-icons-extended` · библиотека иконок весит несколько МБ ради двух картинок

- 2026-10 · Android-токены (4.4): access и refresh — в DataStore Preferences (файл `fuel_tracker.preferences_pb`) **без шифрования**; файл исключён из облачного бэкапа и переноса на новое устройство (`backup_rules.xml`, `data_extraction_rules.xml`) · папка приложения закрыта от других приложений; шифрование (Tink/Keystore) — новая зависимость и заметно больше кода, контракт его не требует. Вернуться, если появятся требования безопасности
- 2026-10 · Android-автообновление токена (4.4): OkHttp `Authenticator` на 401 → `/auth/refresh` → один повтор запроса; refresh под общей блокировкой (параллельные 401 → один refresh); refresh 401 → токены стираются (экраны узнают по `TokenStorage.tokens == null`), нет сети/5xx → токены остаются. Запись — только если refresh-токен не сменился (`replaceIfCurrent`), чтобы «Выйти» во время обновления не воскрешало сессию · стандартный способ OkHttp, экраны ничего не знают о 401

Эндпоинт тот же, контракт не меняется
- 2026-10 · Android-сеть (4.3): `mockwebserver3` (OkHttp, та же версия) — только для тестов · проверять запросы и разбор ответов без настоящего сервера, как требует `09_TESTING.md`

Неизвестное значение enum — ошибка `Unexpected` (контракт нарушен)

- 2026-10 · Заправки (3.4): дата вне месяца листа — 422 `BUSINESS_RULE`, `reason: REFUELING_DATE_OUTSIDE_MONTH`; изменение/удаление заправки, после которого фактический остаток больше доступного топлива, — 422 `FUEL_END_OVER_AVAILABLE` · правила 3 и 4 действуют при любом изменении листа, а не только при вводе остатка

- 2026-10 · ЛУТ (3.3): пагинация `limit` 1..50 (по умолч. 12), `before=YYYY-MM` — строго раньше, `next_before` — месяц последнего листа страницы; «предыдущий лист» для `ODOMETER_GAP` — ближайший более ранний, даже через пропуск месяцев · контракт не уточнял, так проще всего для ленты
- 2026-10 · Ошибки формата поля (минусы, год/месяц вне диапазона, нет `odometer_end_km` при close) — 400; правила, зависящие от данных в БД, — 422 `BUSINESS_RULE` с `details.reason`: `ODOMETER_END_BEFORE_START`, `FUEL_END_OVER_AVAILABLE`, `MONTH_TOO_FAR`, `SHEET_HAS_REFUELINGS`, `WINTER_NORM_NOT_SET` · приложение различает причины по одному полю
- 2026-10 · Закрытый лист: PATCH, close и DELETE → 409 `SHEET_CLOSED`; reopen открытого листа — 200 без изменений; PATCH с тем же сезоном норму не перекопирует; «текущий месяц» — по UTC (`get_now`); по архивному авто листы можно читать и создавать · правило 6 «нормы меняются только при переключении», единое время в проекте
- 2026-10 · Сезон первого листа без явного `season` — по месяцу самого листа, а не по текущему · иначе лист на ноябрь, созданный в октябре, стал бы «летним»

- 2026-10 · Сезонные нормы по образцу старого приложения MyFuel: у авто летняя и зимняя норма; у листа `season`, переключается вручную иконкой ☀️/❄️ и наследуется следующим месяцем; первый лист — по месяцу (`WINTER_MONTHS`, по умолч. 11–3) · зимний период зависит от региона и может начаться в середине месяца — решает пользователь; переключать нужно только 2 раза в год. Альтернатива «автоматически по месяцу» отклонена
- 2026-10 · Нормы и расход на 100 км — 3 знака после запятой (NUMERIC(6,3)), литры и деньги — 2 · реальные нормы вида 10.068; при 2 знаках цвет расхода в пограничных случаях был бы неверным
- 2026-10 · Цвет расхода считает backend: `calc.consumption_status` NORMAL/OVER (≤ нормы — зелёный) · правило в одном месте, Android только красит (правило №10)
- 2026-10 · Цена за литр остаётся обязательной, АЗС — необязательной · решение пользователя: деньги в ЛУТ нужны всегда

- 2026-10 · Расчёты ЛУТ: зависимые поля берут округлённые значения других полей; каждое предупреждение — не больше раза; одометр заправки без конца месяца проверяется только снизу · цифры в карточке сходятся «на глаз», без дублей предупреждений
- 2026-10 · Покрытие тестами считается с `concurrency = greenlet` · иначе coverage не видит код внутри SQLAlchemy async и занижает цифры
- 2026-10 · Авто: список по дате добавления; госномер в верхний регистр; возврат из архива через `PATCH is_archived=false`; неверный UUID в пути — 400 · контракт («любые поля Car») это допускает, другого способа вернуть авто нет
- 2026-10 · Общий тип `Decimal2` (app/schemas/types.py) для литров, денег, норм: вход — строка или число, ≤ 2 знаков; выход — строка «50.00» · одно правило для всех дробных полей API
- 2026-10 · Refresh-токен живёт 90 дней (не 30), срок продлевается при каждом refresh · ЛУТ заполняют раз в месяц — при 30 днях сотрудник разлогинивался бы почти каждый месяц
- 2026-10 · `/auth/logout` всегда 204, даже с недействительным токеном · выход не должен «застревать» в приложении; access-токен истекает сам за 15 мин. Срок JWT сверяется с часами приложения (`get_now`), не системными · единое время для всей логики и тестов
- 2026-10 · Выдача JWT (access + запись refresh в `refresh_tokens`) сделана в задаче 2.2, а не 2.3 · по контракту verify-code сразу возвращает токены; в 2.3 остаются проверка токенов, refresh, logout, `/me`
- 2026-10 · Отключённый пользователь (`is_active=false`) на request-code получает 403 `PHONE_NOT_ALLOWED` · контракт не меняется, SMS не тратится
- 2026-10 · Лимит запросов кода по IP — счётчик в памяти процесса (`SlidingWindowLimiter`), время — зависимость `get_now` · как в 05_AUTH_SMS для MVP; часы подменяются в тестах

- 2026-10 · Запасной вход по паролю (`POST /auth/login`), логин = номер телефона, пароль выдаёт человек командой `python -m app.cli set-password`; пользователь пароль не меняет; тестового аккаунта для пароля нет · если SMS не пришла, задать пароль через приложение невозможно; отдельный логин не нужен — телефон уже уникален. Альтернативы: отдельное поле login, смена пароля в профиле — отклонены для MVP
- 2026-10 · Хэш паролей — `hashlib.scrypt` (stdlib), блокировка 15 мин после 5 ошибок · без новой зависимости (bcrypt/argon2 не нужны для десятков пользователей), защита от подбора

- 2026-10 · Enum-поля в БД — varchar + CHECK (`native_enum=False`), не PostgreSQL ENUM · совпадает с 03_DATA_MODEL (varchar), новое значение добавляется без ALTER TYPE
- 2026-10 · UUID первичных ключей генерирует Python (uuid4), не БД · id известен до INSERT; единые имена ограничений (naming convention) для стабильных миграций
- 2026-10 · uvicorn как ASGI-сервер, база `fuel_test` создаётся init-скриптом PostgreSQL · стандартный сервер для FastAPI; тестовая БД в том же контейнере, как требует 09_TESTING.md

- 2026-10 · Расчёты ЛУТ только на backend · одна точка истины, Android не дублирует формулы
- 2026-10 · Дробные числа в API — строки · исключить ошибки float в литрах и деньгах
