# 07. Экраны и навигация (Android)

## Навигация
```
Splash ──(режим?)──┬── нет ──▶ PhoneScreen ──▶ CodeScreen ──(новый?)──▶ NameScreen ──▶ SyncAfterLogin ─┐
                   │               │                                                                  │
                   │               └──(«Продолжить без входа»)──▶ NameScreen (гость) ─────────────────┤
                   └── GUEST / ACCOUNT ───────────────────────────────────────────────────────────────┤
                                                                                                      ▼
                              (есть выбранное авто?) ── нет ──▶ CarsScreen ◀──▶ CarEditScreen
                                                    └── да ──▶ SheetsFeedScreen
Вход по паролю:
PhoneScreen / CodeScreen ──(«Войти по паролю»)──▶ PasswordLoginScreen ──(имя пустое?)──▶ NameScreen
                                                                     └── иначе ──▶ SyncAfterLogin
SheetsFeedScreen ──▶ RefuelingEditScreen (bottom sheet)
SheetsFeedScreen ──▶ CloseSheetDialog / NewSheetDialog
SheetsFeedScreen ──(иконка авто в шапке)──▶ CarsScreen
SheetsFeedScreen ──(иконка 👤)──▶ ProfileScreen (имя, синхронизация, пароль, «Выйти»)
ProfileScreen (гость) ──(«Войти и сохранить данные на сервере»)──▶ PhoneScreen ──▶ … ──▶ SyncAfterLogin
ProfileScreen ──(«Войдите снова», если сессия истекла)──▶ PhoneScreen ──▶ … ──▶ синхронизация
```
SyncAfterLogin — не отдельный экран, а полноэкранный индикатор «Загружаем ваши данные…» на время
первой синхронизации после входа (`05_AUTH_SMS.md`). Ошибка → «Не удалось загрузить данные» +
«Повторить» и «Продолжить» (данные придут при следующей синхронизации).
Id выбранного авто хранится в DataStore (`selected_car_id`).

## Общие правила UI
- Material 3, светлая и тёмная тема.
- Экраны с данными читают Room и обновляются сами (Flow); состояния `Content` и `Empty`
  (понятный текст + кнопка действия). Ошибок сети на них нет — сеть нужна только для входа,
  синхронизации и смены пароля.
- Ошибки сети (вход, синхронизация, пароль) — текстом из `error.message` сервера, иначе
  «Нет связи с сервером».
- Числа: разделитель десятичных — запятая для отображения (`45,50 л`), ввод принимает и `,` и `.`.
- Клавиатура: для литров/денег — `KeyboardType.Decimal`, для пробега — `KeyboardType.Number`.
- Месяц отображается по-русски: «Октябрь 2026».
- Все строки интерфейса — в `res/values/strings.xml`.

## 1. PhoneScreen
- Поле «Номер телефона» с маской `+7 (___) ___-__-__`, кнопка «Получить код».
- Кнопка неактивна, пока номер неполный. Во время запроса — индикатор на кнопке.
- 403 → «Этот номер не зарегистрирован в организации». 429 → «Повторите через N сек».
- Под кнопкой — текстовая ссылка «Войти по паролю» → PasswordLoginScreen
  (уже введённый номер передаётся туда).
- Внизу — кнопка «Продолжить без входа» (только при первом запуске, не когда гость входит из
  профиля) → NameScreen в гостевом режиме. Подпись мелким текстом: «Данные будут только на этом
  телефоне. Войти и сохранить их на сервере можно позже в профиле».

## 2. CodeScreen
- 6 ячеек для цифр, автоотправка при вводе 6-й цифры.
- Таймер «Отправить код повторно через 0:59», после — кнопка «Отправить ещё раз».
- Ссылка «Изменить номер». Ошибки: «Неверный код», «Код истёк — запросите новый».
- Ссылка «Не пришла SMS? Войти по паролю» → PasswordLoginScreen (с этим номером).
- (Опционально, не MVP) автоподстановка кода через SMS User Consent API.

## 2a. PasswordLoginScreen
- Поле «Номер телефона» (та же маска, что на PhoneScreen; подставляется, если номер уже введён).
- Поле «Пароль» (`KeyboardType.Password`, скрытый ввод, иконка «показать/скрыть»).
- Кнопка «Войти» → `POST /auth/login`; неактивна, пока номер неполный или пароль пустой.
  Во время запроса — индикатор на кнопке.
- Подсказка мелким текстом: «Пароль задаётся в профиле после входа по SMS. Забыли — обратитесь
  к ответственному сотруднику».
- Ошибки: 401 → «Неверный номер или пароль». 429 → «Слишком много попыток. Повторите через N мин».
- Успех: сохранить токены; `is_new_user = true` → NameScreen, иначе → SyncAfterLogin.
- Ссылка «Войти по коду из SMS» → назад на PhoneScreen.

## 3. NameScreen
- Поле «Как вас зовут», кнопка «Продолжить».
- После входа → `PATCH /me` (интернет есть) → SyncAfterLogin. Гость → имя сохраняется только на
  телефоне → CarsScreen.

## 4. CarsScreen
- Список карточек авто: название, госномер, тип топлива, норма. Выбранное — с отметкой.
- Нажатие — выбрать и перейти в ленту ЛУТ. Долгое нажатие/меню — «Изменить», «В архив».
- FAB «+ Добавить авто». Empty: «Добавьте первый автомобиль».

## 5. CarEditScreen
Поля: Название*, Госномер, Тип топлива* (выпадающий список), Объём бака, л*,
блок «Норма расхода, л/100 км»: ☀️ Лето* и ❄️ Зима (необязательно), до 3 знаков (`10,068`).
Подпись под нормами: «Изменение норм не меняет уже созданные месяцы».
Все проверки — в приложении (обязательность, > 0, до 3 знаков); сохранение — в Room, сразу.
```
│ Норма расхода, л/100 км              │
│   ☀️ Лето *       [ 10,068        ]  │
│   ❄️ Зима         [ 11,684        ]  │  ← необязательно
```

## 6. SheetsFeedScreen (главный экран) — лента ЛУТ
- Шапка: название и госномер выбранного авто, кнопка смены авто.
- `LazyColumn` карточек ЛУТ, новые сверху — все листы авто из Room (без пагинации и
  pull-to-refresh: данных мало, сеть не нужна). Итоги каждой карточки считает `SheetCalculator`.
- FAB «Новый лист» → NewSheetDialog с подсказкой `next-prefill` (`06_BUSINESS_RULES.md`).
- Empty: «Листов пока нет. Создайте первый — укажите пробег и остаток топлива».

### Карточка ЛУТ (`SheetCard`)
Карточка компактная (по образцу старого приложения MyFuel); нажатие на карточку раскрывает /
сворачивает подробности. Несколько карточек могут быть раскрыты одновременно.
`calc.*` ниже — итоги, которые посчитал `SheetCalculator` на телефоне (`06_BUSINESS_RULES.md`).

Свёрнутая:
```
┌──────────────────────────────────────────────┐
│ Сентябрь 2026  ⚠                             │  ← месяц крупно, всегда целиком
│ ☀️ Лето  🔒                        ≡ 2    ⋮   │  ← сезон; 🔒 — закрыт; ≡ 2 — заправки
│ Начало месяца:  52 340     │     Расход       │
│ Конец месяца:   53 340     │     10,150       │  ← цвет по calc.consumption_status
│ ──────────────────────────────────────────── │
│ Пробег       Остаток в баке     Заправлено   │
│ 1 000 км     9,00 л             98,50 л      │
│                      ⌄                       │  ← подсказка «можно раскрыть»
└──────────────────────────────────────────────┘
```
- «Конец месяца» — «—», пока не введён; «Пробег» — `calc.mileage_km` или «—».
- «Расход» — `calc.actual_l_per_100km` (3 знака) или «—», если не посчитан.
- «Остаток в баке»: закрытый лист — `calc.fuel_end_l`; открытый — подпись «Доступно» и
  `calc.fuel_available_l`.
- «Заправлено» — `calc.refueled_l`.
- Предупреждения `calc.warnings` — значок ⚠ рядом с месяцем; сам текст — в раскрытой части.

Раскрытая (под свёрнутой частью, с анимацией; ⌄ меняется на ⌃):
```
│ ──────────────────────────────────────────── │
│ Норма 10,068 л/100 км                        │
│ Остаток на начало: 12,00 л                   │
│ Заправлено: 98,50 л · 5 417,50 ₽             │
│ Остаток на конец: 9,00 л                     │  ← «(по норме)», если фактического нет
│ Перерасход 0,82 л                            │  ← > 0 «Перерасход», < 0 «Экономия»
│ 1 км = 5,42 ₽                                │
│ ⚠ предупреждения (если есть)                 │
│                    [ Закрыть месяц ]          │  ← только открытый лист
```

Кнопка **≡ N** (значок списка и число заправок, спокойным серым цветом, без «бейджа»
уведомления; без заправок — только значок) открывает **RefuelingsListSheet** — нижнюю
шторку «Заправки · Июль 2026»:
```
│ 05.07  Лукойл  50,00 л × 55,00 = 2 750,00 ₽ 🗑 │  ← АЗС — если указана
│ 20.07          48,50 л × 55,00 = 2 667,50 ₽ 🗑 │  ← 🗑 — только открытый лист
│ ──────────────────────────────────────────── │
│ Итого: 98,50 л · 5 417,50 ₽                  │
│                       [ + Заправка ]          │  ← только открытый лист
```
Пусто — «Заправок пока нет». Нажатие на заправку (открытый лист) или «+ Заправка» закрывает
список и открывает RefuelingEditScreen; после сохранения список открывается снова с обновлёнными
данными. 🗑 → диалог «Удалить заправку? Заправка 05.07 на 50,00 л будет удалена» → заправка
удаляется из Room → список и карточка обновляются сами. У закрытого листа заправки не нажимаются,
кнопок «+ Заправка» и 🗑 нет.
- **Расход на 100 км** — 3 знака после запятой (`10,150`). Цвет числа и строки
  «Экономия/Перерасход»: `NORMAL` — зелёный, `OVER` — красный, `null` — обычный. Если расход
  не посчитан, в свёрнутой карточке «—», а в раскрытой — пояснение («появится после закрытия
  месяца»; у старых листов без фактического остатка — «не указан фактический остаток»).
- **Иконка сезона ☀️ Лето / ❄️ Зима** в шапке карточки, всегда видна:
  - открытый лист: нажатие переключает сезон (норма копируется из авто) → карточка
    обновляется (норма, расход, цвет). Snackbar: «Сезон: зима. Норма 11,684 л/100 км»;
  - у авто нет зимней нормы → Snackbar «Зимняя норма не указана» с кнопкой «Указать»
    (открывает CarEditScreen этого авто), сезон не меняется;
  - закрытый лист: иконка бледная; нажатие → Snackbar «Месяц закрыт. Сначала переоткройте его».
- Открытый лист: «Доступно» вместо остатка, «—» вместо расхода, в раскрытой части кнопка
  «Закрыть месяц».
- Закрытый лист: значок 🔒, «+ Заправка» в списке заправок скрыта, в меню «Переоткрыть».
- Удаление заправки — кнопкой в её форме, с подтверждением.

### NewSheetDialog
Поля из подсказки `next-prefill`: Месяц, **Сезон** (переключатель ❄️ Зима | ☀️ Лето, выбран как в подсказке —
как у прошлого листа), Пробег на начало, Остаток на начало. Кнопки «Отмена», «Создать».

## 7. RefuelingEditScreen (bottom sheet)
Поля: Дата* (DatePicker, ограничен месяцем листа), Литры*, Цена за литр*, Сумма (считается
автоматически, можно изменить), Пробег по одометру, АЗС, Способ оплаты (чипы: Личные / Топливная
карта / Организация), Комментарий. Кнопка «Сохранить» → заправка пишется в Room → карточка
обновляется сама.

## 8. CloseSheetDialog
Поля: «Пробег на конец месяца, км»* (подсказка: ≥ пробега на начало), «Фактический остаток
в баке, л»* (подсказка: «если бак пуст — 0»; не больше «Доступно топлива»). Кнопка «Закрыть»
неактивна, пока оба поля не заполнены.

## 9. ProfileScreen
Аккаунт:
```
│ Имя        [ Иван Петров           ] [Сохранить] │  ← офлайн; на сервер — при синхронизации
│ Телефон    +7 999 123-45-67                      │
│ ── Синхронизация ─────────────────────────────── │
│ Последняя: 06.10.2026 18:20  (или «ещё не было»)│
│ Не отправлено изменений: 12                      │
│                    [ ⟳ Синхронизировать ]        │  ← индикатор на кнопке во время запроса
│ ── Вход по паролю ────────────────────────────── │
│ Пароль: задан / не задан   [Задать | Сменить]    │
│ ──────────────────────────────────────────────── │
│ Версия 1.0                            [ Выйти ]  │
```
- **Синхронизировать** → `POST /sync` (`06_BUSINESS_RULES.md`, «Синхронизация»). Результат —
  Snackbar «Синхронизировано: отправлено N, получено M»; есть `rejected` → диалог со списком
  «Не отправлено» (что и почему); ошибка сети — «Не удалось синхронизировать. Проверьте интернет»;
  сессия истекла — «Войдите снова» с кнопкой входа.
- **Задать / Сменить пароль** → диалог: «Текущий пароль» (только при смене), «Новый пароль»,
  «Повторите пароль» (скрытый ввод, «показать/скрыть»). Проверки на телефоне: 8..64 символа,
  пароли совпадают. → `PUT /me/password`. Нужен интернет; ошибки — текстом в диалоге
  («Неверный пароль», «Нет связи с сервером»). Успех — «Пароль сохранён. Теперь можно входить
  без SMS».
- **Выйти** → подтверждение «Перед выходом данные будут синхронизированы и удалены с этого
  телефона» → синхронизация → успех: logout, очистка Room и DataStore → PhoneScreen. Не удалось —
  «Выйти не получилось: данные не отправлены на сервер. Проверьте интернет», остаётся в профиле.

Гость:
```
│ Имя        [ Иван                   ] [Сохранить] │
│ ⓘ Данные хранятся только на этом телефоне.        │
│   Удалите приложение — данные пропадут.           │
│        [ Войти и сохранить данные на сервере ]    │
│ Версия 1.0                                        │
```
Блоков синхронизации, пароля и кнопки «Выйти» у гостя нет.
