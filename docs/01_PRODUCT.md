# 01. Продукт

## Цель
Дать сотрудникам организации простой способ вести ежемесячный учёт топлива по личным
автомобилям, которые используются в работе: сколько проехали, сколько заправили, сколько
осталось в баке и какой получился расход.

## Пользователи
- **Сотрудник (user)** — единственная роль в MVP. Видит и редактирует только СВОИ автомобили и ЛУТ.
- *(Позже, не в MVP)* **Администратор/бухгалтер** — просмотр всех ЛУТ, выгрузка в Excel.
- *(Позже, не В MVP) При регистрации Пользователь вводит номер телефона → получает SMS с 6-значным кодом → вводит код →
   попадает в приложение.

## Главный принцип: приложение работает без интернета
Все данные (авто, ЛУТ, заправки) хранятся **на телефоне** и все расчёты делаются на телефоне.
Интернет нужен только для входа, синхронизации и смены пароля. Сервер — хранилище копии
данных: он принимает их при синхронизации и отдаёт при входе с другого телефона; сам ничего
не считает, и никто, кроме приложения, его данные не смотрит.

## Основные сценарии (MVP)
0. **Без входа (гость).** На первом экране — «Продолжить без входа»: пользователь указывает имя
   и пользуется приложением полностью, но только на этом телефоне — без сервера и синхронизации.
   Удалил приложение или потерял телефон — данные пропали (приложение честно об этом говорит).
   Позже гость может войти в аккаунт — все его данные сохранятся и уйдут на сервер.
1. **Вход.** Пользователь вводит номер телефона → получает SMS с 6-значным кодом → вводит код →
   попадает в приложение. При первом входе указывает имя. Сразу после входа приложение один раз
   синхронизируется: на новом телефоне скачиваются данные с сервера, у бывшего гостя — его данные
   уходят на сервер.
   **Вход по паролю** (без SMS): ссылка «Войти по паролю» → номер телефона (он же логин) и пароль.
   Пароль пользователь задаёт сам в профиле (нужен интернет); если забыл — ответственный
   сотрудник сбрасывает его командой на сервере (см. `05_AUTH_SMS.md`).
2. **Автомобили.** Пользователь добавляет автомобиль (название, госномер, тип топлива, объём бака,
   норма расхода летняя и, по желанию, зимняя). Может редактировать и архивировать.
   Выбирает активный автомобиль.
3. **Лента ЛУТ.** После выбора авто открывается прокручиваемый список карточек — по одной на месяц,
   новые сверху. В карточке: месяц, сезон (☀️/❄️), пробег на начало, пробег на конец, кнопка
   «Добавить заправку», список заправок, заправлено за месяц, остаток в баке; после ввода пробега
   на конец месяца — пробег за месяц и расход на 100 км: зелёный — в пределах нормы, красный —
   перерасход.
4. **Новый месяц.** Кнопка «Новый лист» создаёт ЛУТ на следующий месяц; пробег, остаток на начало
   и сезон подставляются из предыдущего месяца (можно поправить).
4а. **Сезон.** Нажатием на ☀️/❄️ в карточке пользователь переключает сезон месяца — лист считается
   по летней или зимней норме авто. Следующие месяцы наследуют сезон, поэтому переключать нужно
   только при смене сезона (осенью и весной).
5. **Заправки.** Добавить / изменить / удалить заправку: дата, литры, цена за литр, сумма,
   (необязательно) показание одометра, АЗС, способ оплаты.
6. **Закрытие месяца.** Пользователь вводит пробег на конец месяца и фактический остаток в баке
   → лист закрывается, показываются итоги. Закрытый лист можно переоткрыть.
7. **Синхронизация.** Только по кнопке «Синхронизировать» в профиле, без напоминаний и без
   автоматики (кроме одного раза сразу после входа). Отправляются только изменения с прошлой
   синхронизации, затем приходят изменения с сервера. Видно время последней синхронизации и
   сколько изменений ещё не отправлено.
8. **Выход.** «Выйти» сначала синхронизирует; если удалось — данные стираются с телефона и
   открывается экран входа. Без интернета выйти нельзя (иначе потеряются неотправленные данные).
9. **Смена телефона.** Вошёл на новом телефоне — получил все свои данные с сервера.

## Вне MVP (не делать, пока не попросят)
- Роль администратора, веб-панель, выгрузка в Excel/PDF, отчёты на сервере.
- Автоматическая синхронизация и напоминания о ней.
- Одновременная работа с двух телефонов (поддерживается только смена телефона).
- Фото чеков, iOS-версия, push-уведомления.

## Нефункциональные требования
- Android 8.0+ (minSdk 26).
- Backend на одном VDS (1–2 vCPU, 1–2 ГБ RAM достаточно).
- HTTPS обязателен для продакшена.
- Пользователей — десятки, не тысячи. Простота важнее масштабируемости.
- Регистрация ограничена: `REGISTRATION_MODE=whitelist` (только телефоны из списка `ALLOWED_PHONES`)
  или `open` (любой номер). По умолчанию — `whitelist`, т.к. приложение для своей организации.
  Гостевой режим к серверу не обращается, поэтому белым списком не ограничен.
